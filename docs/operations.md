# Запуск и остановка

Команды установки и запуска приведены в README. Приложение слушает 127.0.0.1. Для доступа по сети требуется отдельная настройка TLS и доступа, демопароли для этого не подходят. Остановка через Ctrl+C прекращает выдачу новых задач. При следующем старте unfinished задачи возвращаются в очередь с checkpoint. waiting и paused сохраняются.

Время max_seconds означает срок от первого старта до завершения вычислений. Он включает паузу и простой после сбоя. Возобновление не сбрасывает deadline. Сравнение текстов останавливается кооперативно между этапами, генерация проверяет отмену после очередного токена. Уже начатый вызов GPU нельзя считать мгновенно прерванным.

# Резервное копирование

Выполнить `python scripts/backup.py runtime/hr.sqlite backups/hr-2026-10-14.sqlite`. Команда создает новый файл через SQLite backup API, проверяет целостность и печатает SHA-256. Оригиналы PDF находятся внутри БД отдельными записями kind=attachment в Base64, поэтому согласованная копия включает их вместе с извлеченным текстом, снимками задач и аудитом. Это персональные записи и хэши паролей, поэтому копия хранится с ограниченными правами и не попадает в публичный Git.

Для восстановления остановить приложение, сохранить текущую базу отдельно, скопировать выбранную копию в runtime/hr.sqlite, удалить только относящиеся к старой остановленной базе WAL/SHM файлы и запустить приложение. Сначала проверить integrity_check, аудит, состояние заданий и скачивание тестового PDF разрешенным рекрутером. SHA-256 файла должен совпасть с сохраненным document.sha256. Нельзя подменять базу работающего процесса.

# Импорт и хранение PDF

Начальный учебный набор загружается командой `python -m hr_screening.seed --pdf`. Она читает 32 синтетических файла data/resumes, извлекает текст ограниченным парсером и сохраняет оригиналы. Сам набор воспроизводимо создается `python scripts/build_resumes.py`, его manifest связывает ID с SHA-256 и числом страниц.

POST /api/resumes/pdf принимает один multipart-файл и поля name, email, project_id. Скачивание оригинала через GET /api/resumes/{id}/pdf доступно только scoped recruiter. Текст источника конкретной задачи открывается через GET /api/tasks/{task_id}/sources/{resume_id}: изменение текущего резюме не меняет сохраненный снимок. Аудит этих операций содержит метаданные, без текста и Base64. Оригинал не копируется в обычный ответ resume или task.

Лимиты импорта: 5 MiB файла, 6 MiB тела запроса, 20 страниц, 30000 символов извлеченного текста. documents.py запускает pypdf 5.6.0 в отдельном Python -I subprocess с чистым окружением, 8 с wall time, CPU 6/7 с soft/hard, 512 MiB RAM. Два слота разбора принимают работу без ожидания. При 429 и Retry-After: 1 загрузку можно повторить позднее, при 413 нужен меньший файл, при 422 нужно исправить документ. Сканы требуют OCR, которого в пилоте нет; зашифрованный либо поврежденный файл отклоняется.

Не повышать лимиты без отдельного испытания памяти, времени и объема backup. Base64 увеличивает полезный объем бинарных данных примерно в 4/3 раза. Процесс с resource-лимитами и чистым окружением не равен полной OS-песочнице. OCR, другие офисные форматы и более сильная изоляция относятся к развитию.

# Версии и наблюдение

API /api/admin показывает очередь, состояния, число работников и метрики. /metrics доступен администратору. Аудит содержит автора, роль, разрешенную область, действие, версии и итог. Полные тексты и токены в него не записываются. Хэш-цепочка выявляет изменение сохраненных событий, но для защиты от администратора БД нужен внешний неизменяемый якорь.

Обновление начинается с новой версии кода и отдельного каталога весов. После тестов и HR-оценки конфигурация переключается на новую версию. Откат возвращает прежний release и прежние закрепленные веса. На одной машине остановка API при обновлении остается ограничением пилота. Целевой вариант использует несколько API replicas и PostgreSQL.

# Контейнерный профиль

Dockerfile и compose.yaml описывают отдельный вариант запуска с /dev/kfd и /dev/dri, read-only образом, временным /tmp и внутренней сетью. Веса и демонстрационная база подготавливаются на хосте. APP_UID и APP_GID должны совпадать с владельцем runtime, VIDEO_GID и RENDER_GID берутся из групп хоста. Этот профиль проверен синтаксически, сборка образа и отсутствие egress в контейнере в текущий протокол не входят. Фактические GPU-замеры получены при локальном запуске Python.
