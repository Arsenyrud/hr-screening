# Условия приемки

Испытания запускаются на синтетическом наборе. Перед проверкой фиксируются commit, версии моделей, размер пула и режим вычислений. Для боевых резюме нужен отдельный допуск и разметка рекрутеров.

| Код | Проверка | Критерий |
|---|---|---|
| S1 | Вакансия, сравнение, источники, экспорт | waiting, список и точные цитаты, затем completed только после утверждения |
| S2 | 1, 8 и 12 конкурентных задач | Все задачи заканчиваются управляемо, метрики задержки и ошибок сохранены |
| S3 | Утверждение человеком | Выбранные ID, автор, роль и аудит одной транзакцией |
| S4 | Нет навыка, отрицание, противоречие, неизвестный стаж | Нет выдуманного подтверждения, есть замечание или вопрос |
| S5 | Пауза, отмена, просроченный deadline, ошибка модели | Корректный статус, поздний результат не перезаписывает отмену |
| S6 | Чужой клиент и проект, запрещенная роль | 403/404, нет данных, событие access.denied |
| S7 | Аварийный выход процесса после checkpoint | Продолжение с сохраненного этапа, результат waiting |
| O1 | Backup через SQLite backup API | integrity_check=ok, результат и хэш-цепочка совпадают |
| O2 | Откат приложения и модели | Предыдущий release + закрепленные веса + повтор регрессии |
| P1 | 32 синтетических PDF и manifest | Все файлы извлекаются, SHA-256 совпадают, цитаты дословны; профессиональные признаки трех контрольных short-list сохраняются |
| P2 | Скан, зашифрованный, пустой или поврежденный PDF | 422 с понятной причиной, новая запись и вложение не появляются |
| P3 | Файл более 5 MiB или multipart более 6 MiB | 413 до выполнения разбора |
| P4 | Более 20 страниц, 30000 символов, превышение времени/ресурсов | Управляемая ошибка, нет частично сохраненного импорта |
| P5 | Два занятых parser slots | Немедленный 429 с Retry-After: 1, без ожидания в очереди |
| P6 | Роль и подмена проекта при импорте/скачивании | Только recruiter своего tenant/project получает PDF, отказ не раскрывает чужой текст |
| P7 | Ошибка аудита во время сохранения | Одна транзакция откатывает resume, attachment и событие |
| P8 | Backup/restore загруженного PDF | Оригинал включен в копию БД, после восстановления его SHA-256 совпадает |
| P9 | Источник старой задачи после обновления резюме | Scoped API возвращает прежний снимок текста, на котором основана цитата |
| U1 | Фильтры очереди и карточки кандидатов | «Все», «На проверке», «Утверждены» отбирают задания; поиск и выбор сохраняются, карточки показывают основания и вопросы |
| U2 | Вложенная карточка источника и возврат | Back, focus и scroll возвращают пользователя в прежнее место |
| U3 | Опрос статуса во время просмотра/выбора | Нет потери DOM-контекста, текста поиска, выделения кандидатов и фокуса |

Нагрузочные ориентиры ТЗ: 20 активных исполнителей, 8-12 конкурентных задач, создание до 2 с, старт до 5 с, p95 API до 500 мс и не более 0,5% серверных ошибок. Последний baseline-протокол показывает p95 16,43 / 134,40 / 179,33 мс, ошибок 0, наблюдались 20 активных. Исходные 793,9 мс тяжелого профиля сохранены как история до отделения вычислений от API. Короткий синтетический запуск не подтверждает промышленный SLA или 12 параллельных LLM-генераций.

PDF-парсер работает в Python -I subprocess с чистым окружением, лимитом 8 с wall time, CPU 6/7 с soft/hard и 512 MiB памяти. Он извлекает только существующий текстовый слой, не выполняет OCR и не считается полной OS-песочницей. Успех baseline PDF-эксперимента не заменяет прогон MiniLM и Qwen3 по извлеченным документам.

Отдельный инфраструктурный стенд проверяет egress=0 с сетевым захватом, отказ узла GPU, обновление без остановки API, внешний якорь аудита, OIDC и настоящую ATS. Эти проверки описаны в проекте, но текущие тесты приложения их не подтверждают.

runtimeModelOOM также остается непроверенным сценарием. Успешный короткий вызов и обычный пик памяти не доказывают корректную обработку ее исчерпания. Финальные результаты автотестов и отдельных PDF/GPU-прогонов сверяются с evidence и версией приложения.
